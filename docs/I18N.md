# Internationalization

Status: mandatory architecture and first-release policy with an implemented shared localization service. The persistent Library and all preview routes use synchronized `en-US`, `zh-CN`, and `ja-JP` catalogs, switch locale live, persist explicit overrides, and expose a working System Default control. Native-speaker review, accessibility review, and pixel-level visual verification remain incomplete.

## Supported locales and fallback

Required first-release locales:

| Locale | Display name | Role |
| --- | --- | --- |
| `en-US` | English (United States) | canonical source and fallback |
| `zh-CN` | 简体中文 | required complete catalog |
| `ja-JP` | 日本語 | required complete catalog |

Settings offers System Default plus explicit choices for all three. On first launch, negotiate the OS locale, then persist only an explicit user override. Required mappings include:

```text
en-* -> en-US
zh-CN, zh-SG, zh-Hans-* -> zh-CN
ja-* -> ja-JP
unsupported/invalid -> en-US
```

Do not map `zh-TW`/`zh-HK` (Traditional Chinese) silently to Simplified Chinese unless product research approves it; use `en-US` fallback until `zh-TW` exists. Locale tags are parsed/normalized with a maintained standards-aware library, not ad hoc substring rules.

## Frontend-independent architecture

Localization is a reusable service/resource layer, preferably an eventual `teleark-i18n` crate:

```text
Core structured data/error
 -> presentation error/message mapping
 -> Localizer(message_id, parameters, locale)
 -> GPUI or future CLI text
```

Core never returns translated business strings. Persisted statuses/rules are stable locale-neutral enums/values. The localization layer exposes plain owned/shared Rust strings and formatter outputs, not GPUI-specific element types, so multiple frontends can reuse it.

Use a maintained Project Fluent-compatible solution if verified suitable and permissively licensed. Required capabilities are stable IDs, parameters, plural/select rules, fallback, Unicode, parsing/validation, and controlled runtime reload. Do not implement a giant Rust `match`, locale `if` branches in widgets, or manually concatenated translated fragments.

## Resource layout

The intended shape is:

```text
crates/teleark-i18n/
  resources/
    en-US/
      main.ftl
    zh-CN/
      main.ftl
    ja-JP/
      main.ftl
```

Equivalent modular files by domain are acceptable (`library.ftl`, `transfer.ftl`, and so on) if every locale has the same organization and validation loads the complete bundle. `en-US` is the key/variable source of truth.

Message IDs are stable semantic identifiers. Fluent resources use kebab-case IDs, and Rust callers prefer the domain-grouped constants exported from `teleark_i18n::message_ids`:

```text
library-title
library-all-files
library-empty-title
upload-dialog-title
upload-compatibility-mode
transfer-state-verifying
transfer-parts-completed
settings-language-system-default
vault-warning-key-loss
```

The localizer canonicalizes legacy dotted or underscore spellings for compatibility, but new code and resources use the exported constants and canonical hyphen IDs. Do not use ordinal/visual IDs such as `text1`, `left-label`, or `button-43`. Renaming an ID is a code/resource migration, not a casual copy edit.

## Adding or changing a message

1. Choose a domain-oriented semantic ID.
2. Add canonical `en-US` wording and define parameters/selectors.
3. Add reviewed `zh-CN` and `ja-JP` translations in the same change.
4. Call the localizer from the presentation boundary; never persist the result.
5. Add/update structured-error mapping if applicable.
6. Run resource parse, duplicate, completeness, variable, fallback, and negotiation tests.
7. Check affected screens in all three locales for expansion/clipping.

A completed feature may not rely on runtime fallback to hide a missing required translation. Runtime fallback remains a safety net; repository validation fails incomplete required catalogs.

## Variables, plurals, and sentences

Messages own whole grammatical units. Use named typed parameters and Fluent plural/select behavior rather than `count + " files"` or concatenating independently translated fragments.

Conceptual example:

```text
transfer.parts-completed(completed: 25, total: 39)
transfer.flood-wait(retry_after_seconds: 42)
library.files-count(count: 1 or 2)
```

The validator compares variable sets across locales and rejects unexpected/missing required variables. Values are escaped/rendered as text by default; user filenames/captions are parameters, never resource syntax.

## Locale switching

Preferred behavior is live language switching. Changing Settings updates the locale service, invalidates localized view models, and requests a safe full-window rerender/rebuild if that is the cleanest GPUI mechanism. No data migration or reinstall is involved. Persist the explicit override transactionally; “System Default” removes it and renegotiates.

If a verified GPUI constraint requires restart, document the evidence and show a localized restart notice. Runtime changes must not alter Core state, indexed text, or sort/search identity.

## Formatting policy

Central formatters own dates, times, numbers, percentages, file sizes, durations, and rates. GUI components do not format raw values independently.

- Human file/storage sizes and transfer rates use decimal SI units (`kB`, `MB`, `GB`, `MB/s`) to match the product references: base 1000, localized decimal/group separators, normally up to one decimal with precision rules tested around boundaries.
- Exact format/configuration constants use binary IEC units (`MiB`, `GiB`), for example `1900 MiB` application parts and `8 MiB` frames. Never label 1900 MiB as 1900 MB.
- Percentages, counts, dates, times, and durations follow locale conventions through maintained formatters where practical.
- Technical identifiers—BLAKE3/SHA-256 values, package/message IDs, byte offsets in diagnostics, format versions—use canonical ASCII formatting and are not localized.
- Timestamps retain a clear internal UTC instant; display uses the user's selected/system time zone according to settings, never locale as a proxy for time zone.

Rounding must not show `100%` before byte/verification completion. ETA and rates distinguish unknown/unavailable values from zero.

## Source content and search

Never translate or normalize away the identity of Telegram filenames, captions, channel titles, original paths, or user-created collection names. Preserve original Unicode. UI locale changes only interface text and formatting; they do not rebuild/corrupt source metadata or change domain status values.

Search behavior/tokenization is a separate indexed-data concern. Locale-aware UI labels must not be inserted into FTS rows as source content.

## Layout rules

The reference images remain authoritative, but controls must tolerate “上传,” “Upload,” and “アップロード” without locale-specific width hacks. Use flexible text regions, meaningful minimum sizes, wrapping where the design permits, and tooltips/details for intentional filename truncation. Never make translations unreadably small.

Run the seven-screen locale smoke matrix in `UI_GUIDELINES.md`. Accessibility labels, shortcut descriptions, validation, notifications, tooltips, menus, onboarding, and end-user CLI output are all user-facing and require resources.

## Adding a locale

1. Choose a valid BCP 47 tag and define negotiation mappings.
2. Copy the canonical key/variable structure and translate all required messages.
3. Extend display-name resources without self-localizing tags incorrectly.
4. Add parse/completeness/fallback/number/date/size/negotiation tests.
5. Review terminology with a qualified speaker.
6. Run all main-screen layout/accessibility smoke tests.
7. Update this document and release notes/support claims.

Adding a locale is resource/validation/layout work, not a rewrite of Core or GPUI business logic.

## Required automated validation

Normal CI verifies through the `teleark-i18n` test suite that:

- every resource parses and contains no duplicate IDs;
- required locale key sets equal the canonical set;
- referenced and declared variable sets agree;
- fallback to `en-US` and required negotiation cases work;
- unsupported/invalid locales fail safely to `en-US`;
- every structured Core error presentation mapping references a valid ID;
- formatter boundary cases and Unicode parameters are correct.

The current package implements these checks for the embedded resources and structured Core error mappings. Its 20 deterministic tests cover parse/key/variable parity, fallback, negotiation, live switching, error mappings, counts, percentages, decimal SI sizes/speeds, invalid timestamps, and localized date rendering. The GUI resolves Library/import/error/status text through the same catalogs; runtime tests verify explicit override persistence and removal when System Default is selected. Native-speaker terminology review, accessibility review, and pixel-level layout verification remain product work and are tracked separately in `IMPLEMENTATION_STATUS.md`.
