# Internationalization

`teleark-i18n` is the frontend-independent Fluent localization service. GUI and future CLI code render semantic message IDs and structured error mappings; Core never returns localized business prose.

## Catalog and fallback

Resources live at `crates/teleark-i18n/resources/{en-US,zh-CN,ja-JP}/main.ftl`. English is canonical; all three required catalogs must have the same keys and variable sets. A missing required translation fails validation even though runtime fallback is available.

| Input | Negotiated locale |
| --- | --- |
| `en-*` | `en-US` |
| `zh-CN`, `zh-SG`, `zh-Hans-*` | `zh-CN` |
| `ja-*` | `ja-JP` |
| Unsupported/invalid, including unsupported Traditional Chinese | `en-US` |

Settings offers System Default and explicit choices. Locale switches live; only explicit overrides persist. System Default removes the override. A command-line locale wins for that launch. Tags are parsed with the maintained locale library, not substring guesses. Current system detection reads locale environment variables; platform-native locale preference discovery remains a release task.

## Message contract

- Use stable semantic kebab-case IDs, preferably exported domain constants. Legacy dotted/underscore lookup aliases remain supported; new resources use canonical IDs.
- Add/change English, Simplified Chinese and Japanese together. Messages own complete grammatical units, named parameters and Fluent selectors/plurals; do not concatenate translated fragments.
- The current wrapper resolves top-level message values. Terms and attributes need explicit lookup/validation support before use.
- Never persist translated statuses/rules or use translated errors for control flow. Map structured errors at the presentation boundary.
- Menus, accessibility labels, shortcuts, notifications, validation, dialogs, onboarding and end-user CLI output all require catalog entries. Technical identifiers, brand marks and user/source content remain literal.
- Preserve filenames, captions, channel titles, paths and collection names. They are text parameters, not Fluent syntax, and are never rewritten by locale changes.

The TeleArk channel's remote marker is locale-neutral. Its initial human description is localized at creation; later interface language changes do not edit Telegram content or the user's channel title. Files/Raw Files describe two projections over the same channel, not separate storage destinations. About's release record is translated as complete Markdown; its canonical English value equals `CHANGELOG.md`.

## Formatting

Central `format` functions own human dates, counts, percentages, durations, speeds and sizes. SI decimal units (`kB`, `MB`, `GB`, `MB/s`) serve human file/storage display. Exact format/configuration quantities use IEC (`MiB`, `GiB`), such as the 60 MiB current part ceiling and 8 MiB frame size.

Protocol IDs, hashes, offsets and version strings remain canonical ASCII. Unknown rates/ETA are distinct from zero; progress must not round to completion before verification. Internal timestamps are UTC instants; date display uses the OS local time zone through the centralized formatter. Locale changes the date/number presentation, not the time zone.

## Validation workflow

1. Update all three catalogs, caller IDs and structured-error mappings together.
2. Run `cargo test -p teleark-i18n --locked`: parse/duplicates, completeness, variables, fallback, negotiation, formatting, plurals and error mappings.
3. Check static GUI references resolve; resource parity alone cannot detect a misspelled call-site ID.
4. Run affected UI screens in all locales for clipping, wrapping, meaningful filename truncation, keyboard and accessible labels. Follow [UI guidelines](UI_GUIDELINES.md).

Adding a locale requires negotiation, display-name resources, complete translations and all validation above. Do not silently map an unsupported script to another supported language variant.
