# Localization and display formatting

`teleark-i18n` is the frontend-neutral authority for language selection, Fluent messages, structured error messages, numeric formatting and timestamps. User text (names, paths, captions, channel titles and collection names) remains literal; changing the interface language never rewrites persisted values or remote content.

## Registered languages

The single `supported_locales!` registry in `crates/teleark-i18n/src/locale.rs` defines each language's canonical tag, native name, short badge, embedded catalog and completeness policy. Settings and command-line parsing use this registry; do not maintain a separate list in the GUI.

The additional languages cover primary navigation, settings, authentication controls, keychain storage and warnings, channel filters and batch download phases, file details, storage controls, transfer states and progress, recovery controls and common failures. Detailed diagnostic explanations, historical release notes and some secondary flows remain in English. Settings discloses this fallback for incremental catalogs. These counts describe translated source messages, including translated aliases, rather than claiming every message is translated. New message additions change the count; the parser tests remain authoritative for current key and variable coverage.

Every effective catalog resolves all canonical IDs. Existing complete catalogs keep strict source-key parity. Incremental catalogs omit untranslated entries instead of copying English or inserting empty values. Validation rejects unknown keys, duplicate keys, invalid Fluent syntax and changed variable sets. Missing translations use the validated English catalog. The test suite renders every translated Fluent message with representative arguments to catch broken references or selectors without opening another-language interface.

Regional variants select the registered language (for example `es-MX` → `es-ES`, `fr-CA` → `fr-FR`, `pt-PT` → `pt-BR`). POSIX forms such as `de_DE.UTF-8` are accepted. Unsupported languages fall back to English; Traditional Chinese is never silently mapped to Simplified Chinese. Explicit preferences override the system language. The current system discovery uses locale environment variables.

## Add or expand a language

1. Add `resources/<tag>/main.ftl` with actual translations and the same semantic IDs and named variables as English. Use complete phrases and Fluent plural selectors where grammar requires them; preserve literal technical identifiers and user-supplied arguments.
2. Register the tag, native name, badge and completeness policy once in `locale.rs`. Incremental catalogs must cover the tested primary flows and currently at least 650 source messages; set complete only when every canonical ID is translated. Expanding an existing incremental catalog requires no registry or frontend changes.
3. Add appropriate number, grouping, duration and date policies in `format.rs`. For a right-to-left language, add bidirectional-isolation support before registering it; current languages are all left-to-right.
4. For new product messages, update English, Simplified Chinese and Japanese together and translate the corresponding common flow in each incremental catalog. An untranslated incremental entry may be omitted and will fall back to English. Never repurpose an existing ID or change its variables in only one catalog.
5. Run `cargo test -p teleark-i18n --locked`, plus affected frontend tests. Catalog parsing, formatting and negotiation tests may cover every language. Interface tests, screenshots and visual layout review use **English only**, in light mode at 900×600 and actual native full-screen, as required by `AGENTS.md`.

To inspect current coverage without opening any UI:

```sh
python3 - <<'PY'
from pathlib import Path
import re
for path in sorted(Path('crates/teleark-i18n/resources').glob('*/main.ftl')):
    print(path.parent.name, len(re.findall(r'^[A-Za-z][\w-]* =', path.read_text(), re.M)))
PY
```

## Binary byte quantities

All visible byte sizes and byte rates use IEC binary units: **B, KiB, MiB, GiB, TiB, PiB, EiB** and the matching `/s` rates. Each step is exactly 1024. This applies equally to tables, dialogs, inspectors, status bars, charts, logs, tooltips, previews and end-user CLI output. Call `format_bytes` or `format_speed`; do not implement local decimal scaling or label a binary value `MB`/`GB`.

Numeric separators follow the selected language: comma decimals in Spanish, French, German, Portuguese and Russian; narrow/nonbreaking grouping in French/Russian. Binary unit symbols remain IEC symbols in every language. Unknown metrics remain unavailable, never fabricated. Persist raw quantities and locale-neutral values, not translated display strings.
