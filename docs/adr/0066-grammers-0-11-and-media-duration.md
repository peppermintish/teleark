# ADR 0066: Grammers 0.11 and encrypted media metadata

Status: Accepted — 2026-10-16. Adds SQLite schemas 25/26 and Telegram session codec v2 for Community peers. Revised 2026-10-16 to add manifest 3.0 for authenticated playback metadata. Container/part codecs, key wraps, pending envelopes and recovery bundles retain their existing byte formats.

## Context

Grammers 0.11 updates to Telegram API layer 230, replaces `chrono` timestamps with `jiff`, moves retry policy from `ClientConfiguration` to sender-pool connection parameters, changes peer caching to support batches, and adds Telegram Community peers. GPUI Kit 0.7.3 includes the selectable-text implementation used by the desktop inspectors.

Telegram's audio/video document attributes provide duration, but filenames and MIME types do not. The app must not invent duration or decode whole media payloads to display it. Manifest 1.0/2.0 do not contain playback duration. New local Vault uploads need a bounded metadata read to populate duration and useful playback properties, then preserve those properties across restart and database-loss recovery.

## Decisions

- Upgrade the grammers crates together at exactly 0.11.0 and GPUI Kit to exactly 0.7.3. Configure retry policies per sender pool. The primary pool keeps bounded `AutoSleep`; sync uses `NoRetries` so the coordinator owns retry/rate-limit feedback. One-shot authorization confirmation invokes the raw pool handle to avoid starting a retry loop from the check itself.
- Keep the published grammers 0.11.0 pin with a reproducible `vendor/grammers-mtsender` patch, documented with the source archive checksum in `TELEARK_PATCH.md`. The published URL parser can classify a numeric SOCKS IPv4 host as Domain; parsing that IP before DNS avoids a resolver initialization panic even when the app uses its authenticated local gateway. Resolver initialization failures return I/O errors. Preserve IPv4 support and all proxy isolation checks; do not change machine DNS, bypass the gateway, add direct fallback or require IPv6. The source remains MIT OR Apache-2.0, retains upstream headers/licenses, and needs no policy exception. Retire the patch once a published upstream version has equivalent behavior.
- Store Telegram-reported media duration as nullable, non-negative integer milliseconds in `logical_files.duration_ms` and `native_download_tasks.media_duration_ms` (SQLite schema 25). Carry it through normalized Telegram updates, cached file projections, remote upserts, native download history and `LogicalFile`. Old records and sources that omit duration remain NULL. UI uses a compact `M:SS`/`H:MM:SS` formatter; unknown duration is rendered as unavailable, never inferred from a file extension or MIME type.
- Supersede this ADR’s initial decision to defer manifest duration: new completed desktop manifests use **3.0**, independently of part codec **2.0**. Encrypted metadata key 10 carries optional integer playback milliseconds; key 11 carries an optional bounded map of width, height, sample rate in Hz, audio channel count and bit depth. The authenticated envelope declares the manifest version; flags still describe part geometry. Absent properties remain unknown. Retain exact 1.0/2.0 readers and writers for compatibility fixtures and immutable sealed outboxes.
- Read local playback metadata in the retained upload owner after source hashing and durable cancellation registration, before encrypted part transport. Use `nom-exif =3.8.0` (MIT) for MP4/MOV/3GP and MKV/WebM/MKA duration/dimensions, and `lofty =0.24.0` (MIT OR Apache-2.0, default compression feature disabled) for common audio properties. Lofty 0.24 fits the Rust 1.88 baseline; 0.25 requires Rust 1.89. Use content detection, seek past payload where supported, disable tag/artwork collection, and retain only numeric playback properties. Neither library decodes audio/video. Do not persist GPS, device details, free-form tags or artwork. Suppress parser tracing within the probe; emit sanitized phase/outcome events outside it.
- Share a 16 MiB read budget, 8,192 I/O-operation budget and three-second cooperative elapsed-time budget across parsers. Check cancellation around each read/seek. The time budget is checked between I/O calls and cannot interrupt a blocked filesystem call; a blocked owner must not stall another owner. Show reading, read-complete, unavailable or limit-reached transitions in the existing bounded timeline. Unsupported, malformed or limited metadata does not prevent upload. Source identity is rechecked after probing and before publication.
- Carry authenticated duration into managed list projections and show available playback properties as selectable rows in the lateral file-details inspector. Use semantic labels and locale-aware centralized formatters. Keep independent inspector scrolling and access to restore controls at 900×600 and actual full-screen mode.
- Keep old Telegram session bytes unchanged. Session codec v1 remains the writer when no `ChannelKind::Community` occurs. If a Community peer is cached, write codec v2; both versions are readable by this release. A reader that does not know Community must not reinterpret version-2 bytes as version 1. The v1 fixture and round-trip tests use synthetic peer IDs and synthetic key bytes.
- Use GPUI Kit `SelectableText` for detail values, captions, transfer detail rows and inspector summaries. The app's existing `component::Root` owns text-selection scope, Copy action and clipboard integration; tests mount that root and exercise selection and copy rather than only checking an element style.

## Compatibility and migration

Schema 26 adds nullable `vault_downloaded_files.media_duration_ms`. New verified downloads persist authenticated playback duration in the retained Local inventory; local imports read supported metadata and populate the existing schema-25 logical-file field. Keep readers for historical manifests and leave unavailable values unknown. Upgrades 0–25 run automatically with visible transactional conversion and verification. A failing schema-26 step rolls back its DDL/version while retaining files, settings, account scope and old records. Restart and skipped-upgrade tests cover 10/24/25→26, with the generic suite covering every supported start. No final destination file is modified by migration.

Schema 25 adds nullable `logical_files.duration_ms` and `native_download_tasks.media_duration_ms`. The ordered transactional migration is restartable and does not rewrite existing file or ciphertext bytes. Existing rows retain NULL. Native-download output projections carry source duration into the Local list; existing transfer elapsed-duration fields keep their prior meaning. Applications supporting schema 24 reject schema 25 while preserving the database. Tests cover read/write, filtered search projections, restart, migration rollback and automatic upgrade from older versions.

Grammers timestamps cross into TeleArk as Unix milliseconds; persisted timestamps retain their existing locale-neutral units. Existing upload/download transfer data, encrypted containers, parts, key wraps and recovery bundles retain their versioned readers and writers. Completed manifest readers accept 1.0, 2.0 and 3.0; new desktop completion writes 3.0. Old manifests require no rewrite or manual migration and retain unknown playback properties. Older applications reject 3.0 without reinterpreting it. A sealed 1.0/2.0 outbox replays its original envelope and commitment, without reopening the source. An unsealed reservation follows the existing automatic fresh-package/File-Key restart before any new encryption. Pending-upload envelope v1 remains byte-compatible and omits playback properties; before completion they can be re-read from the verified source. Part geometry, remote discovery names/captions and recovery-context versions are unchanged; SQLite advances independently through schemas 25 and 26.

## Verification

Deterministic tests cover duration conversion, DB persistence, old-session v1 fixture compatibility, conditional v2 session writing, GPUI list display, inspector drag selection and clipboard copy. Media tests use generated synthetic MP4/WebM/FLAC/MP3 fixtures and sparse WAV data; exercise malformed input, bounded reads/seeks, cancellation and blocked-owner isolation; freeze manifest 3.0 bytes, reject version/property tampering, preserve 1.0/2.0 fixtures and outbox replay, and recover metadata after real crypto/SQLite publication and restart. Inspector tests cover audio/video metadata and scrolling at 900×600 and actual full-screen. Workspace tests, strict Clippy, formatting, documentation and `cargo deny` are required before the tagged release. Hosted platform packaging and Store ingestion remain governed by the existing tagged release workflow.
